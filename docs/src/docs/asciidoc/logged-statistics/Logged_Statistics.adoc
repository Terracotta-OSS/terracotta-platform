== Overview

This "design" document summarizes the meeting notes and decisions for the story TDB-19513 about logging some information periodically in the server logs (statistics, server states, etc).

A log line has to be printed every X minutes (period), that contains some useful information for defect troubleshooting.

This log line has ot be easily readable and parseable, each data recorded within a fixed width slot in this line, always a the same slot index in the line

== Content of the log line

=== Marker

The marker helps identify these log lines in the log file.

Can be something like: `STATS`

=== Period

The period will by 5 minutes by default but can be configurable through a system property called `org.terracotta.statistics.logging.period`

The period will be se tin seconds and displayed in the log line in seconds.

Currently existing:

- com.terracottatech.frs.ReportFsyncLatenciesInSecs (FRF): 5 mins
- com.terracottatech.store.server.usage.log.interval (Tc Store): 5 mins

Note: a TC property on the server could be changed by config-tool:

```bash
> config-tool set -connect-to foo -setting tc-properties:org.terracotta.statistics.logging.period=120
```

=== Stripe Topology

- Fixed ordering list of servers, ordered by server name
- Example: [A,P,P] for 1 active and 2 passive servers
- Example: [A,P,P,T] for 1 active, 2 passive and 1 relay server

Note: a passive server does not see the other servers so it can't see the stripe topology and will display its state alone

=== Server States

[%header,cols="1,2,3"]
|====================
| Code | State | Mnemonic

| ?  | UNKNOWN | Server state unknown

| S  | STARTING | Initial starting state
| D  | DIAGNOSTIC | Final diagnostic state
| A  | ACTIVE | Final diagnostic state
| P  | PASSIVE | Final diagnostic state
| T  | RELAY | Final diagnostic state, Relay transmits => TX
| R  | REPLICA | Final diagnostic state, Replica receives => RX

| AR | ACTIVE_RECONNECT | Transient active reconnect state
| PS | SYNCHRONIZING | Transient passive sync state

| SB | START_SUSPENDED | Blocked starting state
| AB | ACTIVE_SUSPENDED | Blocked active state
| PB | PASSIVE_SUSPENDED | Blocked passive state
| RB | REPLICA_SUSPENDED | Blocked replica state

|====================

Most of the time the logs will contain teh final states.

=== Statistics

Definitions:

- `COUNTER`: always increases
- `METER`: always increases and resets to 0 at the end of the period (like a utility meter)
- `GAUGE`: value that can increase or decrease
- Long.MAX_VALUE == 9223372036854775808 (19 chars)

Statistics to log:

[%header,cols="1,3,1,1,2,2"]
|====================
| Code | Name | Type | Source | Characteristics | Notes

|  V | Connected Voters | GAUGE | Core | 0..Long.MAX_VALUE | (current value) only if voters
| +V | Voter Join Count | METER | Core | 0..Long.MAX_VALUE | (+delta during period) only if voters
| -V | Voter Left Count | METER | Core | 0..Long.MAX_VALUE | (-delta during period) only if voters

|  P | Physical Connections      | GAUGE | Core | 0..Long.MAX_VALUE | (current value)
| +P | Physical Connections Created   | METER | Core | 0..Long.MAX_VALUE | (+delta during period)
| -P | Physical Connections Dropped | METER | Core | 0..Long.MAX_VALUE | (-delta during period)

|  C | Connected Clients      | GAUGE | Core | 0..Long.MAX_VALUE | (current value)
| +C | Client Connect Count   | METER | Core | 0..Long.MAX_VALUE | (+delta during period)
| -C | Client Disconnect Count| METER | Core | 0..Long.MAX_VALUE | (-delta during period)

|  F | Entity Fetches       | GAUGE | Core | 0..Long.MAX_VALUE | (current value)
| +F | Entity Fetch Count   | METER | Core | 0..Long.MAX_VALUE | (+delta during period)
| -F | Entity Unfetch Count | METER | Core | 0..Long.MAX_VALUE | (-delta during period)

|  S | Connected Servers | GAUGE | Core | 0..Long.MAX_VALUE | (current value)
| +S | Server Join Count | METER | Core | 0..Long.MAX_VALUE | (+delta during period)
| -S | Server Left Count | METER | Core | 0..Long.MAX_VALUE | (-delta during period)

| +EIC | Total Entity Invocation Count | METER | Core | 0..Long.MAX_VALUE | (+delta during period)

| +CIC | Cache Entity Invocation Count | METER | Core | 0..Long.MAX_VALUE | (+delta during period)
| +SIC | Store Entity Invocation Count | METER | Core | 0..Long.MAX_VALUE | (+delta during period)
| +QIC | Sequence Entity Invocation Count | METER | Core | 0..Long.MAX_VALUE | (+delta during period)

|====================

== Log Format Requirements

- Information logged in a single line, fixed-width field so that it is easy to follow the changes lines after lines
- Numbers logged right-aligned
- Cell should have a some few characters to label the info logged (see mnemonics above)
- deltas (- or +) tracked with a sign, like `Clients[0010,+003,-002]`
- cell width: minimum 4 digits for gauges, min 3 digits for deltas with +/- sign
- when the number increases to more than the displayable number digits, we increase the cell width by 1
- The topology of the stripe with server states inside should be at the start of the line
- The log format must be easy to process also with CLI tools

To make it easier to find all these lines and the period,the log line starts with:
- a marker
- the unix timestamp
- the number of seconds since the last logged line

== Selected Format amongst the proposed ones

- Single delimiter between major fields
- Consistent field extraction
- Colon separates label from value within fields
- Comma separates gauge components (current, +delta, -delta)
- Fixed field positions for reliable parsing
- Fixed field widths for consistent parsing
- Right-aligned numbers
- Optimal for `awk -F'|'`, `cut -d'|'` and grep processing
- Zero padding

[source]
----
# Pipe-Delimited (|)

STATS:<unix>:<seconds>|A,P,P|V:0001,+003,-002|C:0010,+003,-002|F:0025,+010,-005|S:0003,+000,-000|EI:+234|TI:+567
----

**Parsing Examples (with awk):**

[source,bash]
----
# Extract STATS lines:
grep 'STATS:'
# Extract period:
awk -F'|' '{print $1}' | awk -F':' '{print $2}'
# Extract topology:
awk -F'|' '{print $2}'
# Extract voter count (current):
awk -F'|' '{print $3}' | awk -F':' '{print $2}' | awk -F',' '{print $1}'
# Extract voter delta+:
awk -F'|' '{print $3}' | awk -F',' '{print $2}'
# Extract client count (current):
awk -F'|' '{print $4}' | awk -F':' '{print $2}' | awk -F',' '{print $1}'
# Extract fetch count (current):
awk -F'|' '{print $5}' | awk -F':' '{print $2}' | awk -F',' '{print $1}'
# Extract server count (current):
awk -F'|' '{print $6}' | awk -F':' '{print $2}' | awk -F',' '{print $1}'
# Extract EI value:
awk -F'|' '{print $7}' | awk -F':' '{print $2}'
# Extract TI value:
awk -F'|' '{print $8}' | awk -F':' '{print $2}'
----

**Parsing Examples (with grep):**

[source,bash]
----
# Extract STATS lines:
grep 'STATS:'
# Extract period:
grep -oP 'STATS:\K[0-9.]+'
# Extract topology:
grep -oP '\|[A-Z,]+\|' | head -1 | tr -d '|'
# Extract voter count (current):
grep -oP 'V:\K[0-9]+' | head -1
# Extract voter delta+:
grep -oP 'V:[0-9]+,\K\+[0-9]+'
# Extract voter delta-:
grep -oP 'V:[0-9]+,\+[0-9]+,\K-[0-9]+'
# Extract client count (current):
grep -oP 'C:\K[0-9]+' | head -1
# Extract client delta+:
grep -oP 'C:[0-9]+,\K\+[0-9]+'
# Extract client delta-:
grep -oP 'C:[0-9]+,\+[0-9]+,\K-[0-9]+'
# Extract fetch count (current):
grep -oP 'F:\K[0-9]+' | head -1
# Extract fetch delta+:
grep -oP 'F:[0-9]+,\K\+[0-9]+'
# Extract server count (current):
grep -oP 'S:\K[0-9]+' | head -1
# Extract EI value:
grep -oP 'EI:\K[0-9]+'
# Extract TI value:
grep -oP 'TI:\K[0-9]+'
----
